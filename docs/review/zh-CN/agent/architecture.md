# 补丁架构

## 开发输入

`Initialize-AtGSource.ps1 -GamePath <Steam 原版> -Refresh` 会将构建所需的当前原版文件复制到已忽略的 `source/`。它会拒绝在存在活动中文补丁事务时执行，以避免把打过补丁的输出当成源输入。源清单只记录来源，绝不用于拒绝玩家的安装目录。

## 原子构建

`Build-Patch.ps1` 将每个生成文件写入同级暂存目录。构建契约会验证文本、托管重写、运行时组件、配置节点和 ClanCard 别名所需输入与输出哈希。只有通过完整验证的暂存目录才能替换 `patch/`；构建失败会保留原有补丁。替换完成后，它会刷新源派生的组合目录，以防运行时显示映射条目和持久的 KnownText 定位符发生漂移。

## 玩家事务

安装器根据结构特征识别 AtG，在复制前为每个受影响文件建立快照，在第一次覆盖前写入已准备清单，并验证所有已安装哈希。卸载器恢复这些快照，并在所有恢复均得到验证前保留恢复数据。旧版归属规则涵盖历史补丁专有产物和 ClanCard 别名。

## 验证与发布

`Invoke-AtGVerification.ps1` 默认使用 `Localization` 档位。它只根据任务交接中显式给出的 `ChangedPath` 值——从不读取脏工作树差异——选择本地核心以及受影响的文本、组合、托管、字体、自动化或文档检查。未知路径会被记录，且保留核心检查。每项玩家可见的汉化仍会捕获源、构建、以事务方式安装并运行主菜单烟测，除非指定 `-StaticOnly`。

当显式路径仅被分类为文档路径时，`Localization` 会改用无游戏的静态分支：不捕获源、不构建、不安装也不烟测。混合路径集或未分类路径集仍使用保守的常规游戏门禁。

`Release` 仅由明确的发布请求选择。它保留完整静态套件、全目录/进度审计、发布包和事务恢复回归，之后进行相同的真实事务与烟测。两种档位都会在捕获游戏状态前恢复锁定依赖，因此纯工具链失败不会接触选定游戏目录。事务失败会恢复捕获的文件、清单和备份树。门禁将所选检查、结果和阶段耗时写入任务本地 `.tmp` 证据，以供清理交接，而不是写入测试结果知识文档。

`Publish-AtGRelease.ps1` 只接受干净且已同步的 `main`；它运行完整门禁，通过经 AST 检查的依赖清单导出自包含脚本，并使用 `--force-with-lease` 推送一段新的独立最小历史。
