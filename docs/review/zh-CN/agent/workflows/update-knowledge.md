# 工作流：更新知识

## 目的

任何持久项目事实变更时运行：来源位置、补丁行为、组合规则、安全决定、术语、操作
流程或测试证据。将事实保持精简，并放在唯一所属记录中。

测试会话总会在重试或最终报告前调用本工作流，但测试只是一个输入。它不是测试结果
日志、测试前阶段，也不替代所有者的事实记录。

## 首先读取

- `docs/agent/knowledge-index.md`
- 变更文件清单及变更事实的证据
- 仅当触发是测试会话时读取最新测试会话交接

## 按触发或变更读取

| 触发/变更 | 更新/读取所有者 |
| --- | --- |
| 场景通过、失败、移动或受限 | `black-box-tests.md`、选定接口专题、场景 JSON；需要时读特质状态 |
| 新来源、候选、绑定或精确操作数 | `text-sources.md`、匹配来源专题及 SQLite catalog 操作 |
| 组合/富文本规则 | `translations/composite-text-rules.json`，直接查询 `EntryPointId` 与 `RuleId` |
| 崩溃、资产、字体、设置、加载生命周期 | `crash-risks.md`、匹配细节专题和所需 operations 专题 |
| 术语或措辞决定 | `translation-style.md` |
| 历史被拒绝操作数 | `text-sources/localization-safety.md` 和 `localization-safety-registry.json` |
| 清理/证据保留 | 仅清理工作流交接 |

## 步骤

1. 确认变更事实及其权威证据：来源/catalog 记录、已变实现、用户决定或测试交接。
2. 更新最小所属机器/文档记录；不得在本工作流中创建同一事实的第二份历史。
3. 输入为测试结果时，将通过的增量覆盖移入现有所有者。失败时记录观察到的最终
   格式以及候选来源或明确无匹配。组合文本保留 `EntryPointId` 和 `RuleId`。
4. 两个静态输入任一变更后，重建并验证
   `translations/concept-key-translations.json`。
5. 仅在源数据变化时刷新 SQLite catalog。不得生成或读取用户审查导出；用户可独立
   导出。保留手动 `LocalizedFormat`、Rule ID、状态和备注。
6. 可见缺陷已文本化后，用清理交接摘要替换长截图引用；仅在未解决且无法可靠描述的
   视觉缺陷时保留图像。
7. `AGENTS.md` 和知识索引只作路由文档。将新事实放入其单一所有者，而不是多个工作
   流文件。
8. 不要为一次性文本界面或事故创建专题文档。保留其精确 SQLite 定位器和当前任务
   交接。
9. 不得向 `current-status.md` 添加单项本地化修复或用户主导的人工测试状态；该文件
   仅保留仓库级重构验证。项目保留在当前交接或场景所有者中。
10. 测试结论失败时，将更新的知识交回评估/修复；否则继续触发此次知识更新的工作流
    或最终报告。
