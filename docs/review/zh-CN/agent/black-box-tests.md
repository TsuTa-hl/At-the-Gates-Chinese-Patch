# 黑盒测试策略

这是路由与策略索引。场景坐标和可执行点位保存在 `black-box-scenarios.json`；
接口专用验收标准保存在 `black-box/interfaces.md`。

## 默认验证边界

- 除非明确指定 `-StaticOnly`，`Invoke-AtGVerification.ps1` 始终进行真实游戏
  主菜单烟测。
- 主菜单烟测证明启动、补丁加载和基本进程稳定性；它不证明游戏内措辞、布局、
  悬浮、存档加载或每一条 UI 路径。
- 黑盒场景回放需要选择加入；不能仅因为构建或烟测成功就运行。
- 创建随机世界、发现坐标和反复探索运行均须用户明确批准。

## 获准执行场景时

1. 只选择受影响的 Active Focus 接口及其声明的点位。
2. 使用指定固定存档和已批准的绝对坐标。
3. 每次悬浮最多等待三秒；通过时保留文本/裁剪证据，只有状态变化或失败才保留
   全窗口截图。
4. 重试或最终报告前，将结果写入其所属的接口或场景记录。

## 覆盖状态

- `Active`：已选入用户批准的回放。
- `Completed`：对声明的验收规则有当前视觉证据。
- `Deferred`：为可追溯性保留，但默认不选。
- `Discovery`：仅为候选路由，不构成验证声明。

## 视觉门禁

对已测试界面，拒绝原始键、未解析标签、乱码、可安全本地化的英文、人为中文
空格、裁剪或损坏的递归悬浮。生成名称、ID、版本、URL 和已记录的逻辑敏感残留
仅在其所有者记录明确允许时才是例外。
